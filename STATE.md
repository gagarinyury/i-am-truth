# Я есть Правда / I Am Truth

Заявка на Google **All Things Agentic Hackathon** (devpost, дедлайн 31.08.2026, $190k).
Тема хакатона: агенты, работающие в фоне, разбирающие тяжёлые датасеты, автоматизирующие
сложные асинхронные workflow.

Это не спецификация — это путь исследования. Ничего ниже не финально, всё — гипотезы,
которые можно и нужно опровергнуть по ходу дела.

## Что уже эмпирически доказано (не гипотеза, а факт)

27.08.2026, Gemini 2.5 Pro на Vertex (`merci-prod`, `us-central1`, ADC рабочего аккаунта,
эндпоинт `v1beta1`), тест на McDonald et al. (GLP-1 и рак груди, JCO Oncology Practice 2026)
против собственного экспертного разбора из 5 пунктов:

- **Round 1** (голый абстракт): модель закрыла 3.5/5 пунктов, но перепутала направление
  confounding by indication (угадала "healthy user", по факту было наоборот — "sicker user").
- **Round 2** (тот же промпт + appendix-таблицы): закрыла 4.5/5, ошибка направления
  исчезла сама, без изменения промпта.

Вывод: **moat не в промпте, а в принудительном вытягивании full-text/appendix-данных**.
Это единственная часть проекта, которая проверена на реальных данных, а не придумана.
Подробности и точные цифры — в памяти `project_methodology_critic_app.md`.

## Черновая архитектура слоёв (гипотеза, не догма)

Как отправная точка для сборки — не как чертёж, который нельзя менять:

```
Layer 0 — Orchestrator: приём DOI/PDF, состояние джобы, асинхронный фан-аут
Layer 1 — Retrieval:   Metadata Agent · Full-Text Agent (Europe PMC) · Table Extractor
Layer 2 — Fast Critic: только abstract → кандидатные паттерны + флаг "нужен full-text"
Layer 3 — Verifier:    full-text + Stats Tool (function-call, не LLM-арифметика)
Layer 4 — Adversarial: Defender vs Prosecutor → Arbiter оставляет то, что выжило
Layer 5 — Confidence:  CONFIRMED / PLAUSIBLE-UNVERIFIED / REFUTED на каждый финдинг
Layer 6 — Report Synth: финальный отчёт в духе Letter-to-the-Editor
```

Если по ходу сборки часть слоёв окажется избыточной (например, Layer 2 и 3 можно слить,
или Defender/Prosecutor не дают прироста качества относительно одного Verifier) —
резать без сожаления. Радар судей поощряет реальную мультиагентность, а не количество
слоёв ради количества.

## Кубики найдены (не изобретать заново)

Прошёлся по каждому слою с вопросом «есть ли готовое» (принцип из CLAUDE.md):

- **Layer 1 retrieval** — `paper-search-mcp` (github.com/openags/paper-search-mcp) — готовый MCP-сервер
  для поиска/скачивания статей (arXiv/PubMed/bioRxiv), втыкается в ADK как тул напрямую.
- **Europe PMC RESTful API** — бесплатно отдаёт full-text+таблицы+supplementary в XML/JSON
  для open-access подмножества. Референс парсинга таблиц из JATS XML — R-пакет `tidypmc`
  (логику воспроизвести на Python, не изобретать свой парсер с нуля).
- **Unpaywall / CrossRef / Semantic Scholar API** — fallback-цепочка для DOI без full-text в PMC.
- **GROBID** (открытый, self-hosted) — конвертирует произвольный PDF → TEI-XML с таблицами,
  если статьи вообще нет в открытых базах. Закрывает риск №2 выше — не "либо PMC, либо ничего".
- **Layer 3 verifier, доп. тулы** — `statcheck` (проверка согласованности p-value/df),
  `GRIM`/`GRIMMER`/`SPRITE` (проверка математической возможности заявленных mean/SD) —
  готовые статистические проверки другого класса ошибок, не наш конфаундинг, но даром.
- **Layer 0 async/batch** — Cloud Run Jobs (run-to-completion батч) + Cloud Tasks (очередь
  с ретраями) + Cloud Workflows (если многошаговая оркестрация между сервисами) —
  свою очередь/шедулер не писать.

- **Vertex AI Search / Agent Builder** — есть Trial-кредит €855 на рабочем аккаунте
  (действует до мая 2027, только под этот продукт). Проверено по документации 27.08.2026,
  уточнено 27.08.2026 (второй заход) — важно различать два сценария:
  - **Сценарий А (плохой):** заливать сырые PDF и доверять OCR/layout-parser Google
    самому находить и парсить таблицы — расплющивает строка/столбец в текстовые чанки,
    точность для пересчёта чисел (Charlson 19.7 vs 10.4) под риском.
  - **Сценарий Б (хороший, выбран):** извлекать таблицы САМИМ через Europe PMC JATS XML/
    GROBID (точные числа сохранены), заливать уже чистые структурированные данные
    (markdown-таблицы / JSONL) в датастор — и вот тут Google берёт на себя векторизацию,
    индексацию и семантический retrieval, отменяя необходимость городить свою векторную
    БД (Chroma/pgvector/FAISS) и свой retrieval-код. Это и есть законное применение кредита.
  Итоговое разделение труда: **Extraction** (свой код, точность) → **Storage+retrieval**
  (Vertex AI Search, инфраструктура, тратит кредит) → **Verifier** (Stats Tool, пересчёт).

## Стек Google — что реально в официальной документации (27.08.2026)

Не додумано, проверено по google.github.io/adk-docs (→ adk.dev), Google Cloud blog,
Google Codelabs и странице resources самого хакатона:

- **Наше разделение на слои — официально рекомендуемый паттерн ADK**, не самодеятельность:
  доки прямо предупреждают, что «stuffing all tools into a single agent's system prompt
  degrades reasoning quality», и советуют делегировать специализированным суб-агентам.
- **Long-running/async — готовый примитив ADK**, не своя очередь: `background=True`
  сразу отдаёт interaction ID, снимает reasoning loop на сервер, клиент опрашивает
  результат асинхронно. Заменяет план с Cloud Tasks для Layer 0 — просто используем это.
- **Firestore SessionService** — официальная встроенная интеграция ADK для хранения
  состояния джобы между шагами пайплайна. Не нужна своя БД под это.
- **VertexAIMemoryBankService** — долгосрочная память между сессиями через Gemini.
  ГИПОТЕЗА (не проверено, не решено): можно копить туда библиотеку уже найденных
  паттернов confounding между разными статьями — система умнела бы от прогона к прогону.
  Совпадает с темой вебинара хакатона «self-evolving agents» (20.08.2026). Проверить
  на практике, не считать готовым решением заранее.
- **`VertexAiSearchTool` отдаёт цитаты бесплатно** — ответ приходит с `groundingMetadata`
  → `groundingChunks`/`groundingSupports`, готовая привязка предложение→источник.
  Закрывает Layer 6 (Report Synth) почти без своего кода.
- **Cloud Run — официально одобренный хост для агентов** (docs.cloud.google.com/run/docs/ai-agents),
  закрывает обязательное требование хакатона о proof of Cloud infra.
- **Cost-guidance с самой страницы resources хакатона:** Gemini Flash где можно (дешёвые
  слои — Fast Critic), Pro — где нужна глубина (Verifier/Adversarial); scale-to-zero;
  serverless vector search; budget alerts; выключать сервисы после сабмишена.

**Конкуренты, проверено что НЕ делают нашу задачу:** scite.ai (smart citations,
support/contrast/mention — не считает NNT/RR, не проверяет direction of confounding),
SciScore (reporting-чеклисты, не количественный пересчёт). Ниша «пересчитать confounding
по цифрам из appendix» свободна — не значит, что задача решена кем-то другим за нас.

### Уровни доказательности — и цена каждого, измеренная, а не назначенная

| Уровень | Что достали | Доля класса | Качество разбора |
|---|---|---|---|
| **L1** | full-text + таблицы приложения | 22% | **4.5 / 5** |
| **L2** | полный основной текст без приложений | 27% | **3.5 / 5** |
| **L3** | только абстракт и метаданные | 50% | **3.0 / 5** |

**Уровни — это не «хуже/лучше», это механика.** Каждый открывает ровно те пункты,
которые в нём физически лежат:

| Пункт | абстракт | full-text | +приложение |
|---|---|---|---|
| P3 prevalent-user · P5 ARR/NNT | 1.0 | 1.0 | 1.0 |
| P4 компаратор + BMI (Table 2) | 0.5 | **1.0** | 0.5 |
| P1 история рака груди (Appendix) | 0.5 | 0.5 | **1.0** |
| P2 sicker-yet-fewer (Appendix) | **0.0** | **0.0** | **1.0** |

**Самое важное: ошибка направления держится и на L2.** P2 = 0.0 не только на абстракте,
но и на полном тексте статьи — модель уверенно пишет «healthy user effect», пока не
увидит Appendix Table 1. Полный текст **не спасает**; спасает только приложение.
→ Половина статей класса (L3) обречена на правдоподобный, но неверный вывод, если не
дотянуться до приложения. **Это и есть измеренная цена moat-слоя.**

**Побочно:** P4 падает с 1.0 до 0.5 при добавлении приложения — рост объёма входа
размывает внимание. Тот же эффект был в исходном ручном тесте на 2.5 Pro. Прямой
аргумент за узких суб-агентов вместо одного большого промпта (D-06, F-14).

### Что это даёт продукту

Уровень доказательности становится частью выхода: `CONFIRMED` достижим только на L1,
на L3 честный максимум — `PLAUSIBLE-UNVERIFIED`, и отчёт прямо говорит, каких именно
таблиц не хватило и что они бы уточнили. Наполняет содержанием Layer 5, который до сих
пор был просто списком меток.
